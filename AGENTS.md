# oxide

An optimized AI coding agent CLI written in Rust.

## Layout

The repository is a Cargo workspace. Shared agent code lives in
`crates/core/`; the terminal binary in `crates/cli/` (`main.rs`, `tui/`,
`theme.rs`, `uninstall.rs`); the Tauri desktop app in `crates/desktop/`
(GUI-free `manager.rs`/`turn.rs` plus the feature-gated `gui` shell). The Cargo
package names are `oxide-core`, `oxide` (the CLI), and `oxide-desktop`. The VS
Code extension in `editors/vscode/` is a separate pnpm/TypeScript package, not a
Cargo workspace member: it drives the installed `oxide` binary as
`oxide --mode json -p` and so shares the same on-disk configuration and session
tree without linking `oxide-core`. The CLI and desktop link `oxide_core`
directly (`config`, `session`, `runner` for starting a turn, and `theme_view` for
themes as CSS-ready colors).
The desktop resolves project trust from the same `trust.json` the CLI uses and
asks **Trust this project?** before loading a project's `.oxide` agents,
commands, skills and plugins, so its harness matches the CLI instead of being
silently dropped. It accepts image/PDF attachments the way the CLI does — paste
from the clipboard or pick files — by passing them to `runner` as inline content
parts (the webview has no on-disk path for a pasted image), and previews each one
as a clickable thumbnail. Assistant replies render Markdown as HTML, and both
inline and bare `http(s)` links open in the system browser through the `open_url`
command, since the webview cannot navigate to a remote page itself.

- `crates/cli/src/main.rs` — CLI entry (clap). Non-interactive `-p/--print`, `--mode json`, and `--mode rpc` modes plus TUI dispatch; the `mcp`, `sessions`, `plugin` (including `plugin marketplace`), and `uninstall` subcommands. Provider login is TUI-only (`/login`, `/logout`), matching Pi.
- `crates/core/src/mcp_config.rs` — `oxide mcp add/list/get/add-json/remove/auth`: reads and writes MCP servers in the native `.oxide/mcp.json` files (`--scope project|global`), merging sources for listing in the same precedence the runtime loads (Claude Code global, `~/.oxide`, the platform config dir, then the project), with a global file reported once as global when the project root resolves to the home directory; `auth` and `remove` keep a pinned `--scope` inside that scope's files in both layouts (`--scope project` covers a Claude Code `.mcp.json` as well as `.oxide/mcp.json`, so a name defined in both scopes resolves to the requested one), while an unpinned command searches every source in precedence order. `add` also accepts the Claude Code-style `oauth` fields (`--oauth-client-id`, `--oauth-client-secret`, `--callback-port`, `--oauth-scope`, `--redirect-uri`).
- `crates/core/src/config.rs` — `Config` struct; loads `config.json` from the Oxide config dir (`dirs::config_dir()/Oxide`, e.g. `~/.config/Oxide` on Linux, `~/Library/Application Support/Oxide` on macOS) plus `OXIDE_*` / provider env overrides. Provider presets cover OpenAI/GPT, DeepSeek, Anthropic, Portkey, and Z.AI/GLM (`OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `ANTHROPIC_API_KEY`, `PORTKEY_API_KEY`, `ZAI_API_KEY`); Portkey also supports custom gateways/config IDs and model catalogs, and Z.AI is the second provider with a bundled catalog (`GLM_FALLBACK_MODELS`) for `/models`. Defines the `Reasoning` enum (`auto` / `off` / `low` / `medium` / `high`, set via `--reasoning`, `OXIDE_REASONING`, or config), composes the system prompt (a `# Definition of Done` section that forbids reporting unobserved work and requires confirming the outcome of any state-changing action — edits/builds, pull requests, comments and reviews, releases, deployments — before claiming success and holds a review fix until it is committed and pushed before the reply in the thread, a `# Scope` section that keeps commits and PRs limited to the paths the task touched and forbids blanket staging, tool-use guidance that steers toward the dedicated `read`/`grep`/`find`/`ls` tools over compound shell commands (including codebase searches, which a repo-root shell `grep -r` runs through build output and `.git/` while the tools skip both and honor `.gitignore`), and the loaded ecosystem — listing skills, commands and subagents for model auto-invocation), resolves `/commands` (including `agent`/`subtask` routing and `/skill:<name>`), and loads context-compaction config from `settings.json` and `.oxide/settings.json`. Switching providers remembers the model and custom endpoint last used with each one (`provider_models` and `provider_base_urls` in `config.json`, with the active provider's endpoint mirrored to `base_url`) so each login keeps its own model and gateway, and `for_provider` builds a copy of the config pointed at another logged-in provider for catalog queries.
- `crates/core/src/auth.rs` — stores provider API keys/tokens for any number of providers side by side in `auth.json` in the Oxide config dir (mode 0600); keys are resolved after env vars and before the config file. Authentication is TUI-only (`/login`, `/logout`), matching Pi: `connect` also writes the active provider to `config.json` so the next launch uses it, `select_stored` adopts a provider that is already saved so switching between logged-in providers never asks for the key again, and `stored_providers` lists them. `canonical_provider` maps aliases onto the preset names (`gpt`/`gpt-4o` → `openai`, `port-key` → `portkey`, `glm`/`z.ai`/`zhipu`/`bigmodel` → `zai`). There is no `oxide auth` subcommand.
- `crates/core/src/ecosystem/` — discovers and loads configuration from project and global scope: the native Oxide layout (`.oxide/`, `AGENTS.md`, `.oxide/mcp.json`) plus the Claude Code layout (`.claude/`, `CLAUDE.md`, `.mcp.json`) for compatibility. Context files (`AGENTS.md`/`CLAUDE.md`, with `AGENTS.override.md` replacing its directory) are collected by walking every ancestor directory down to `cwd`, and `.oxide/SYSTEM.md`/`APPEND_SYSTEM.md` replace or extend the system prompt. Covers instructions, commands, prompt templates (`prompts/*.md` with Pi-style argument expansion), agents/subagents, skills (`SKILL.md`), MCP servers and plugins. Installed plugin packages contribute their `commands/`, `agents/`, `skills/`, and MCP servers — read from the manifest `mcpServers` or a plugin-root `.mcp.json` in either the wrapped or bare-map form. Project-scope resources are gated behind project trust via `ecosystem::load_opts`. This repository keeps its own agents, commands, prompts, skills and plugins in `.oxide/`; user-facing configuration guidance lives in `docs/cli.md`.
- `crates/core/src/trust.rs` — project trust: `TrustStore` persists per-directory decisions in `trust.json` (closest ancestor wins), `requires_trust` detects project-local resources, `resolve` applies the CLI override plus `defaultProjectTrust` (read from `settings.json`), and untrusted projects reload without project resources (context files still load).
- `crates/cli/src/theme.rs` — semantic TUI color themes: built-in `dark`/`light` (built from `oxide_core::theme_view` so they match the desktop), custom `.oxide/themes/<name>.json` (color names or `#rrggbb`), selected with `--use-theme` or `/theme`. Slots cover focus, speakers, success, tools, errors, supporting text, borders, tool panel backgrounds (`tool_pending_bg`/`tool_success_bg`/`tool_error_bg`), the Portkey spend bar (`usage_bar_bg`/`usage_bar_fg`/`usage_bar_label`), thinking levels, and `thinking_text` for reasoning blocks.
- `crates/core/src/agent.rs` — agent loop: stream the model, execute requested tools, and feed results back until the model stops calling tools or a batch reports `terminate`. Read-only tool calls in a batch run in parallel (results kept in call order) while mutating tools stay sequential; a `Steering` queue injects user messages typed mid-run before the next model call, and a batch whose results all set `terminate` ends the turn. Hosts the agent-level `task` (subagent), `skill` (on-demand load), `command` (model-invoked commands/prompt templates; `subtask` commands run as subagents), `memory`, and `diagnostics` tools; `run` returns a boxed future so subagents can recurse (capped by `MAX_TASK_DEPTH`), and `run_subagent` runs a `subtask` command in an isolated context. A `Runtime` bundles the MCP registry, plugin host, session log, snapshots, LSP manager, the steering and follow-up queues, and the approval callback. Provider-reported token usage (input/output, cache tokens, and cost) is forwarded as `AgentEvent::Usage`, `ThinkingDelta` forwards streamed reasoning and `Retrying` a transient failure about to be retried (the failed attempt's partial text is dropped, and the last attempt's text is recorded to the session when the retry budget is exhausted), `SubagentActivity` carries a nested subagent's tool call up to the originating view (the `task` tool otherwise emits nothing until it returns), and auto-compaction appends a `compaction` entry to the session branch. A `VerificationState` tracks files edited in a run until each is read back, inspected from the shell (a `git diff`/`git show`/`grep` naming the file confirms just that file) or covered by a build/test/lint command, and a table of `DONE_RULES` covers side effects that outlive the workspace (`gh pr create`/`glab mr create`, comments and reviews, releases, deployments and publishes) until a matching status command reads their outcome; if the model tries to finish with any unconfirmed it gets one hidden system reminder (a `# Definition of Done` note) to verify before summarizing, and a provider that answers that reminder with no answer ends the run with the summary already in hand instead of surfacing `the model returned an empty response` on top of a complete reply. A `scope` rule flags blanket staging (`git add -A`/`--all`/`.`/`:/`, `git commit -a`) until a `git status`/`git diff --staged`/`git show` review confirms what is staged. A review reply that ships an edit stays unconfirmed until `git push` delivers it, so a fix left uncommitted while a review is answered is not reported as addressed; a reply command itself (`gh pr comment`/`review`, a POST to the `/replies` endpoint, `glab mr note`) is held while the repository has tracked modifications or unpushed commits (which also covers shell edits like `sed -i` or a formatter), so the thread is not answered before the branch has the fix; a single-branch clone's missing remote-tracking ref is resolved by asking the remote for the branch tip with `git ls-remote` (and accepting a tip the local commit is an ancestor of), so a fix that was actually pushed is not held forever. A repeated build/test command in the same run is flagged with a note rather than silently re-run.
- `crates/core/src/llm/` — model client. `client.rs` dispatches by provider: OpenAI-compatible chat completions (OpenAI, DeepSeek, Portkey, Z.AI/GLM, custom) and the Anthropic Messages API (`anthropic.rs`, converting internal messages to content blocks and parsing its SSE events, and marking the system prompt, the last tool, and the newest message with `cache_control: {"type":"ephemeral"}` so each turn reuses the cached prefix instead of re-reading the whole conversation; the OpenAI-compatible path sends the session id as `prompt_cache_key` for direct OpenAI and as `x-session-id`/`x-client-request-id` headers for gateways, so those providers also get cache affinity, and on a Claude model behind a non-OpenAI endpoint it translates the same Anthropic `cache_control` breakpoints into the OpenAI-shaped request so Portkey/OpenRouter can cache the prefix). Applies the configured reasoning level: OpenAI-compatible `reasoning_effort` and Anthropic adaptive or extended thinking, with Anthropic thinking blocks replayed on later turns and a DeepSeek turn's reasoning replayed as `reasoning_content` on every later request (its thinking mode answers a request that drops an earlier turn's reasoning — tool call or plain answer alike — with a 400, since the request carries tools); GLM instead toggles `thinking.type` and maps levels onto its own `low`/`high`/`max` scale, asking forced-thinking models (GLM-5.3 and later, via `glm_forces_thinking`) for the lowest effort because they reject `disabled`. Streaming goes through `StreamHooks` (`text`, `thinking`, `retry`) so the caller can show work in progress: reasoning deltas (`reasoning_content`/`reasoning`/`reasoning_text`, normalized by `Delta::reasoning`) are merged into one Anthropic-shaped `thinking` block and forwarded as `AgentEvent::ThinkingDelta`; `types::push_thinking` grows that block in place by mutating its `Value::String`, since rebuilding the block per fragment would copy the whole trace and make a long reasoning stream quadratic, and `types::set_thinking_signature` records the signature Anthropic attaches to it. `read_sse` splits the byte stream with `drain_lines`, which hands each complete line to the caller and compacts the buffer once per chunk instead of after every line. A stream that drops without a TLS `close_notify` is remembered as an abrupt end: a turn whose sentinel or stop reason already arrived is returned, but an abrupt close before either is still an incomplete (retryable) turn rather than a partial success, and a plain truncated body is still an error. A retryable failure emits `Retry { attempt, max, delay }` before backing off; a retry may follow an attempt that already streamed text or reasoning, so each front-end drops the assistant or thinking item still in progress when it sees the retry, and the retry streams fresh instead of extending the partial output. `stream_chat` retries transient failures (network errors, truncated streams, 429/5xx) with backoff, retries a turn that carries neither text nor tool calls (`assistant_turn_is_empty`), and only turns empty/truncated streams or in-band `error` payloads into errors once the retry budget is exhausted; an empty or reasoning-truncated turn is reported as the downcastable `NoAnswer` error so a caller that sent a best-effort request can tell it apart from a real failure. A turn whose provider stop reason is the output limit (`finish_reason`/`stop_reason` `length`/`max_tokens`, captured on `AssistantTurn`) instead retries with a doubled `max_tokens` up to 32768, since a reasoning model that spent the whole budget thinking would only truncate again at the same cap. The Anthropic path shares the empty-turn check and treats a `message_delta` stop reason as completion, so a dropped stream is retried instead of returned as an empty turn.
- `crates/core/src/mcp.rs` — MCP runtime: connects configured servers over stdio or HTTP, initializes JSON-RPC sessions, and exposes remote tools (`<server>__<tool>`). Remote servers with an `oauth` block attach a bearer token per request.
- `crates/core/src/mcp_oauth.rs` — OAuth 2.0 authorization-code + PKCE for remote MCP servers: metadata discovery, loopback callback, token exchange/refresh, and `mcp-oauth/<server>.json` storage (mode 0600). The callback answers with a self-contained branded page (semantic color tokens, light and dark via `prefers-color-scheme`, status icon, headline, message naming the server, a monospace block for the provider's error detail, a best-effort `window.close()` after success, all text HTML-escaped, no external assets) plus `Cache-Control: no-store`.
- `crates/core/src/media.rs` — multimodal attachments: dependency-free base64, image/PDF MIME detection, `@path` reference extraction, and a best-effort OS clipboard image grab (`pngpaste` / `wl-paste` / `xclip`). `optimize_image` downscales an oversized PNG/JPEG/WebP (long edge 1568, dimensions parsed from the header) with `sips` on macOS or ImageMagick/ffmpeg on Linux in a private randomly named temp directory that is removed on drop, falling back to the original, so a pasted screenshot is not base64-encoded and stored at full resolution; `content_part_from_data_url` turns a desktop data URL back into an image/PDF part.
- `crates/core/src/clipboard.rs` — system clipboard writes for the TUI: always emits an OSC 52 sequence (wrapped in a DCS passthrough under tmux/screen, so copies survive SSH) and additionally tries a native helper (`pbcopy`/`osascript`, `wl-copy`/`xclip`/`xsel`). A copy reports itself with a dim `ChatItem::Status` tip, since `App.status` only renders while the agent is busy.
- `crates/core/src/memory.rs` — persistent cross-session memory store (project + user scope) under `memory/` in the Oxide config dir, with dependency-free tf-idf search.
- `crates/core/src/notify.rs` — best-effort desktop toast for a completed agent turn: `send` runs the platform notifier on a detached thread (Notification Center via `osascript` on macOS, `notify-send` plus the freedesktop `complete` sound via `canberra-gtk-play`/`paplay`/`aplay`/`ffplay` on Linux, a WinRT toast with `Notification.Default` audio on Windows). `load_config` resolves `notifyOnComplete` and `notifySound` from the global and project `settings.json` (project wins per key) with `OXIDE_NOTIFY_ON_COMPLETE`/`OXIDE_NOTIFY_SOUND` overrides; both default on. The TUI `/notify [on|off]`, `/notify sound [on|off]`, and `/notify test` commands mutate the running config and persist the flags to the global `settings.json` through `save` (`OXIDE_SETTINGS_FILE` overrides the path). The TUI only toasts for real agent runs (internal work like `/compact` and branch summaries sets no `App.notify_on_finish`), using a short title pulled from the newest assistant reply (its first non-empty line, with Markdown markers stripped) as the body instead of the whole summary.
- `crates/core/src/session.rs` — Pi-compatible session storage under `sessions/<project>/` in the Oxide config dir. Each file is a JSONL tree: a `session` header followed by `message`, `compaction`, `branch_summary`, `session_info`, `model_change`, and `thinking_level_change` entries carrying `id`/`parentId`/`timestamp`. The last entry is the active leaf; appending adds a child of the leaf, `branch_with_summary` moves the leaf and appends a branch summary, and `context`/`messages` walk the leaf path with the latest compaction applied. Sessions are resumed via `-c/--continue`, `-r/--resume` (session picker), `--session <path|id>`, or `/resume`; `list` returns picker summaries (id, name, preview, message count), `delete`/`rename` manage sessions, `rewrite` rewrites a session as a linear chain, and `fork` seeds a new session from a message slice (used by `--fork`, `/fork` and `/clone`). Appends are fsynced and recover from a partial trailing line.
- `crates/core/src/sessions.rs` — non-interactive session management (`oxide sessions list/delete/compact/merge`) for stale-session cleanup; `delete` filters by id/`--all`/`--older-than`, `compact` summarizes older history into a summary plus recent tail (one LLM pass per session), and `merge` concatenates two sessions or summarizes the second one first.
- `crates/core/src/snapshots.rs` — shadow-git snapshots (bare repo under `snapshots/<project>/` in the Oxide config dir) committed after each agent step; `/undo` and `/redo` in the TUI restore file changes.
- `crates/core/src/permission.rs` — parses per-agent `permission` rules into allow/ask/deny and decides per tool + subject; `ask` prompts in the TUI unless `auto_approve` is set.
- `crates/core/src/compact.rs` — Pi-style context compaction. Walks back from the newest message until `keepRecentTokens` is reached, summarizes the older span with a structured handoff format (including cumulative read/modified file lists; the format request is sent after the wrapped transcript, matching Pi, so the summarizer does not continue the conversation), and never cuts between a tool call and its result. Settings live under `compaction` in `settings.json`/`.oxide/settings.json` (`enabled`, `reserveTokens`, `keepRecentTokens`, per-model `modelOverrides`), with `OXIDE_COMPACTION_*` env overrides. Auto-compaction runs in the agent loop once provider-reported usage crosses `contextWindow - reserveTokens`; it appends a `compaction` entry to the session branch anchored at `firstKeptEntryId`, and the session rebuilds the outgoing view from the leaf path. Branch summarization reuses the same structured format: `/tree <n>` branches the current session in place (appending a `branch_summary` entry) and `/fork <n>` creates a new session seeded with the summarized abandoned path. Manual compaction is `/compact [focus]` (TUI) and `oxide sessions compact`.
- `crates/cli/src/tui/markdown.rs` — dependency-free Markdown renderer for assistant messages: parses headings, paragraphs, fenced code, ordered/unordered/nested lists (with `☐`/`☑` task markers), blockquotes, rules, pipe tables, and inline bold/italic/strike/code/links/autolinks into styled `ratatui` lines wrapped to the pane width. `render_with_prefix` merges the `◆ oxide` speaker label onto the first line, and unclosed delimiters stay literal so a reply renders cleanly while it streams.
- `crates/core/src/diff.rs` — dependency-free line diff for the TUI: `preview(old, new)` returns `None` when unchanged, a one-line summary when either side exceeds `MAX_DIFF_LINES`, otherwise an LCS-based unified-style preview that keeps `CONTEXT` lines around each change and inserts `⋯` gap markers between disjoint hunks.
- `crates/core/src/html.rs` — dependency-free HTML to Markdown/plain-text conversion for `webfetch`: a small tag parser, entity decoding, and a renderer for headings, paragraphs, lists, tables, links, images, code, and blockquotes.
- `crates/core/src/lsp.rs` — minimal LSP client (rust-analyzer, typescript-language-server, pyright, gopls) that reports diagnostics; a `diagnostics` tool is exposed and `write`/`edit` append diagnostics for the edited file. A cached server that exits or whose pipe breaks is evicted from the manager (killing the child) and a fresh one is connected before the call is retried, so a one-off crash does not turn every later edit into `Broken pipe`; EOF while awaiting diagnostics is treated as a disconnect rather than a clean result.
- `crates/core/src/plugin.rs` — plugin runtime: loads discovered JS/TS plugins under bun/node with an embedded harness and dispatches `tool.execute.before` / `tool.execute.after` hooks. An `after` hook can rewrite the output and set `output.terminate` to end the turn; a `status` hook returns keyed strings for the footer's third row.
- `crates/core/src/pricing.rs` — model prices for the footer's `$cost` segment. Ships a small default table (USD per million tokens, including the GLM models) overlaid by a `modelPrices` map in `settings.json`/`.oxide/settings.json`; unknown models cost 0 and the segment is omitted.
- `crates/core/src/portkey_usage.rs` — the Portkey spend status bar. `/usage` opens a settings dialog in the TUI (`Enabled`, `User`, `Metadata`, `Budget`, `Currency`, `API key`, `Endpoint`; the typed `/usage on|off|user|budget|currency|key|metadata` forms still work) (it only runs while a Portkey provider is logged in, since it reads that account's spend); settings and the API key live in `portkey-usage.json` in the Oxide config dir (mode 0600, `OXIDE_USAGE_FILE` override). `spend` queries `GET <base_url>/analytics/graphs/cost` with `x-portkey-api-key` filtered by the configured user metadata (`_user` by default) for the local day and month, and the bar adds the session's own `$cost`; the key falls back to the active Portkey credential, the budget is formatted in the configured currency (`usd`/`cny`), and the bar refetches every 60s and after each turn.
- `crates/core/src/plugin_registry.rs` — Claude Code-style plugin packages and marketplaces: `oxide plugin` subcommand plus the TUI `/plugins` and `/marketplaces` surfaces manage marketplaces (`.oxide/marketplace.json` preferred, `.claude-plugin/marketplace.json` compatible) and installed plugins (`.oxide/plugin.json` preferred, `.claude-plugin/plugin.json` compatible, bundling commands, agents, skills, MCP servers, and command hooks) under `<config>/Oxide/plugins/`. `marketplace_overview()` shapes each marketplace and its plugins (with local install/enable state) for the `/marketplaces` browser, whose two-pane overlay lists marketplaces on the left and the selected marketplace's plugins on the right (Tab switches pane, Enter installs/removes/toggles, Ctrl+U fetches a git marketplace's latest manifest via `update_marketplace`, Ctrl+A adds, Ctrl+X removes, Ctrl+R reloads the local view). Typing filters the focused pane, with plugin names matched before descriptions. Installed plugins load into the ecosystem before project resources; manifest hooks are translated into a generated JS shim run by the hook host.
- `crates/core/src/tools.rs` — tool specs and execution under Pi-style names (`read`, `write`, `edit`, `bash`, `grep`, `find`, `ls`, `webfetch`) plus connected MCP tools; legacy aliases (`read_file`, `write_file`, `patch`, `list_dir`, `glob`) are accepted via `canonical_tool_name`, which every name comparison routes through. `execute(call, cwd, &McpRegistry, &Progress)` returns a `ToolOutput` (text plus optional image/PDF media parts, an optional `DiffPreview` for `write`/`edit`, and a `terminate` flag; `read` attaches images/PDFs); `bash` streams stdout/stderr through `Progress`. Output is capped centrally in `execute` by lines (`MAX_OUTPUT_LINES`) and bytes (`MAX_OUTPUT_BYTES`): `bash` keeps its tail so the exit code survives, other tools keep the head, and dropped content is written under `truncated/` in the Oxide config dir (`OXIDE_TRUNCATION_DIR`, retained 7 days) with a pointer in the result. `read` splits lines longer than `MAX_LINE_LEN` into continuation chunks and pages via `offset`/`limit`, so a minified JSON line can be read through instead of being cut off, and its output budget reserves a line for the `… more lines; use offset=` pointer so the continuation hint is never trimmed. Argument shapes models get wrong are tolerated: `offset`/`limit` accept a numeric string or a range array (`[820, 850]`, which sets the span), and `edit` repairs a stringified `edits` array that was closed with one brace too many (`[{"oldText":…}}]`). A non-exact `oldText` still lands when only trailing whitespace differs or it was copied from `read` without stripping its `N|`/`N+|` numbering; a genuinely stale one fails with the closest region (its line range and raw text) to copy. A `bash` command that hits its timeout returns the output it produced before being killed instead of discarding it, plus a hint that steers the retry to a narrower command (a directory scope, a build-output exclusion, or the `grep`/`find` tools) instead of letting the same one time out again. A failed command whose output shows an unresolved relative import (`Cannot find module './...'`) gets a hint: when the Node require stack names a script outside the working directory the hint steers to a script inside the project or an absolute path, and otherwise it steers to checking the specifier, since Node resolves `require('./...')` against the script's own directory, not the working directory. `read`/`ls`/`find`/`grep` accept absolute paths; `ls` renders symlink targets as `name -> target`; `grep` matches a literal substring by default (set `regex: true` for a regular expression) and prefers `ripgrep` when it is on `PATH`, falling back to a parallel built-in walker that sniffs and skips binary files.
- `crates/core/src/cli.rs` — Pi-compatible non-interactive surface: `@file` argument expansion, the `--tools`/`--exclude-tools` `ToolFilter`, Pi-shaped JSON event framing (`--mode json`) with usage events and the `thinking_done` step marker (`ThoughtDone`), and the `--mode rpc` JSONL loop. `-p/--print` buffers a step's text until it commits (a tool call or the turn ending) and clears it on a retry, so a dropped stream never duplicates a partial answer on stdout.
- `crates/cli/src/uninstall.rs` — removes oxide's binary and data for `oxide uninstall`: detects Cargo/Homebrew/prebuilt installs, honors `--keep-config`/`--keep-data`, and previews with `--dry-run`.
- `editors/vscode/` — a standalone TypeScript (pnpm) VS Code extension, not a Cargo workspace member. It drives the installed `oxide` binary as `oxide --mode json -p` with the prompt on stdin, so it inherits the CLI's provider logins, `config.json`, `settings.json`, project trust, sessions, context and MCP servers without linking `oxide-core`: `src/extension.ts` registers the commands, status bar and editor actions; `src/chat.ts` is the controller that owns the transcript, the running turn and the queued follow-ups; `src/chatView.ts` is the `WebviewViewProvider` (HTML shell, CSP, message bridge, `openUrl`/`reveal`), registered once for each of the chat's two panes — `oxide.chat` in the activity bar and `oxide.chatSecondary` in the secondary side bar beside Copilot Chat, with both ids shared through `src/core/views.ts` and asserted against the manifest by `src/test/views.test.ts`, since a view VS Code contributes without a matching provider is an empty panel; the controller broadcasts every view message to all attached views, so either pane follows the same turn, `oxide.openChat` raises the pane already visible and falls back to the activity-bar one where the `secondarySidebar` contribution point does not exist, and the ids must stay in step with `contributes.viewsContainers`/`contributes.views`; `src/cli.ts` locates the binary (`PATH`, then `~/.local/bin`/`~/.cargo/bin`) and streams a turn's JSONL; `src/core/` is pure, webview-free and unit tested under `node --test` — `protocol.ts` maps Pi-shaped events (`session`, `thinking`, `thinking_done`, `message_update`, `tool_call`/`tool_execution_update`/`tool_execution_end`, `usage`, `auto_retry_start`, `compaction`, `error`, `agent_end`) into a transcript state machine and small view deltas, `args.ts` turns `oxide.*` settings into `--model`/`--agent`/`--reasoning`/`--approve`/`--tools` flags, `prompt.ts` assembles `--- path[:range] ---` context blocks and resolves a message's own `@path` references (files inline, images/PDFs as ## Conventions

- Rust 2021 edition, 4-space indent, default rustfmt style.
- Errors use `anyhow::Result` with `.context(...)` / `.with_context(...)` for human-readable messages.
- Do not add comments unless they explain non-obvious intent.
- Keep changes small and focused; verify with `cargo test` and `cargo clippy`.
- Built-in file/shell tools and connected MCP tools are registered in `tools::specs(&McpRegistry)` and dispatched in `tools::execute(call, cwd, &McpRegistry, &Progress)`. Tool names are canonicalized with `tools::canonical_tool_name`, which accepts Pi names (`read`, `write`, `edit`, `ls`, `find`) and legacy names (`read_file`, `write_file`, `patch`, `list_dir`, `glob`); permission rules, concurrency checks, and TUI rendering must go through it. `edit` is targeted text replacement (`edits[].oldText` must match uniquely against the original file) and stays separate from the unified-diff `patch` tool. Matching is byte-exact first, then a line-wise pass that ignores trailing whitespace, and a block copied from a numbered `read` listing has its `N|`/`N+|` prefixes stripped (from the replacement text too); leading indentation is never ignored, so a replacement cannot silently lose its indentation. A non-unique match is still rejected, naming the occurrence line numbers, an absent one names the closest region (its line range and raw text, so copying it back applies exactly), and every failing edit in a batch is reported together while nothing is written. `find`/`grep` honor `.gitignore`; `grep` prefers `ripgrep` when available and otherwise uses a parallel built-in walker. The agent-level `task`, `skill`, `command`, `memory`, and `diagnostics` tools are defined and dispatched in `crates/core/src/agent.rs`.
