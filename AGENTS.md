# oxide

An optimized AI coding agent CLI written in Rust.

## Layout

- `src/main.rs` — CLI entry (clap). Non-interactive `-p/--print`, `--mode json`, and `--mode rpc` modes plus TUI dispatch; the `mcp`, `sessions`, and `plugin` subcommands. Provider login is TUI-only (`/login`, `/logout`), matching Pi.
- `src/mcp_config.rs` — `oxide mcp add/list/get/add-json/remove/auth`: reads and writes MCP servers in the native `.oxide/mcp.json` files (`--scope project|global`), merging sources for listing. `add` also accepts the Claude Code-style `oauth` fields (`--oauth-client-id`, `--oauth-client-secret`, `--callback-port`, `--oauth-scope`, `--redirect-uri`).
- `src/config.rs` — `Config` struct; loads `config.json` from the oxide config dir (`dirs::config_dir()/oxide`, e.g. `~/.config/oxide` on Linux, `~/Library/Application Support/oxide` on macOS) plus `OXIDE_*` / provider env overrides. Provider presets cover OpenAI/GPT, DeepSeek, Anthropic, and Portkey (`OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `ANTHROPIC_API_KEY`, `PORTKEY_API_KEY`); Portkey also supports custom gateways/config IDs and model catalogs. Defines the `Mode` enum (`build` / `plan` / `auto-edit`, set via `--mode`, `OXIDE_MODE`, or config) and the `Reasoning` enum (`auto` / `off` / `low` / `medium` / `high`, set via `--reasoning`, `OXIDE_REASONING`, or config), composes the system prompt (adding plan-mode instructions), resolves `/commands` (including `agent`/`subtask` routing), and loads context-pruning config from the global config dir plus `.oxide/dcp.json`.
- `src/auth.rs` — stores provider API keys/tokens in `auth.json` in the oxide config dir (mode 0600); keys are resolved after env vars and before the config file. Authentication is TUI-only (`/login`, `/logout`), matching Pi: `connect` also writes the active provider to `config.json` so the next launch uses it. There is no `oxide auth` subcommand.
- `src/ecosystem/` — discovers and loads configuration from project and global scope: the native Oxide layout (`.oxide/`, `AGENTS.md`, `.oxide/mcp.json`) plus the Claude Code layout (`.claude/`, `CLAUDE.md`, `.mcp.json`) for compatibility. Context files (`AGENTS.md`/`CLAUDE.md`, with `AGENTS.override.md` replacing its directory) are collected by walking every ancestor directory down to `cwd`, and `.oxide/SYSTEM.md`/`APPEND_SYSTEM.md` replace or extend the system prompt. Covers instructions, commands, prompt templates (`prompts/*.md` with Pi-style argument expansion), agents/subagents, skills (`SKILL.md`), MCP servers and plugins. Project-scope resources are gated behind project trust via `ecosystem::load_opts`. This repository keeps its own agents, commands, prompts, skills and plugins in `.oxide/`; user-facing configuration guidance lives in `docs/configuration.md`.
- `src/trust.rs` — project trust: `TrustStore` persists per-directory decisions in `trust.json` (closest ancestor wins), `requires_trust` detects project-local resources, `resolve` applies the CLI override plus `defaultProjectTrust` (read from `settings.json`), and untrusted projects reload without project resources (context files still load).
- `src/theme.rs` — semantic TUI color themes: built-in `dark`/`light`, custom `.oxide/themes/<name>.json` (color names or `#rrggbb`), selected with `--use-theme` or `/theme`. Slots cover focus, speakers, success, tools, errors, supporting text, borders and thinking levels.
- `src/agent.rs` — agent loop: stream the model, execute requested tools, feed results back (`MAX_STEPS = 25`). Read-only tool calls in a batch run in parallel (results kept in call order) while mutating tools stay sequential; a `Steering` queue injects user messages typed mid-run before the next model call, and a batch whose results all set `terminate` ends the turn. Hosts the agent-level `task` (subagent), `skill` (on-demand load), `memory`, `diagnostics` and `compress` tools; `run` returns a boxed future so subagents can recurse (capped by `MAX_TASK_DEPTH`), and `run_subagent` runs a `subtask` command in an isolated context. A `Runtime` bundles the MCP registry, plugin host, session log, snapshots, LSP manager, the steering and follow-up queues, and the approval callback. Provider-reported token usage is forwarded as `AgentEvent::Usage`.
- `src/llm/` — model client. `client.rs` dispatches by provider: OpenAI-compatible chat completions (OpenAI, DeepSeek, Portkey, custom) and the Anthropic Messages API (`anthropic.rs`, converting internal messages to content blocks and parsing its SSE events). Applies the configured reasoning level: OpenAI-compatible `reasoning_effort` and Anthropic adaptive or extended thinking, with Anthropic thinking blocks replayed on later turns.
- `src/mcp.rs` — MCP runtime: connects configured servers over stdio or HTTP, initializes JSON-RPC sessions, and exposes remote tools (`<server>__<tool>`). Remote servers with an `oauth` block attach a bearer token per request.
- `src/mcp_oauth.rs` — OAuth 2.0 authorization-code + PKCE for remote MCP servers: metadata discovery, loopback callback, token exchange/refresh, and `mcp-oauth/<server>.json` storage (mode 0600).
- `src/media.rs` — multimodal attachments: dependency-free base64, image/PDF MIME detection, `@path` reference extraction, and a best-effort OS clipboard image grab (`pngpaste` / `wl-paste` / `xclip`).
- `src/memory.rs` — persistent cross-session memory store (project + user scope) under `memory/` in the oxide config dir, with dependency-free tf-idf search.
- `src/session.rs` — durable append-only session log (JSONL) under `sessions/<project>/` in the oxide config dir; model history is reconstructed from it and resumed via `-c/--continue`, `-r/--resume` (session picker), `--session <path|id>`, or `/resume`. `list` returns picker summaries (id, name, preview, message count), `delete`/`rename` manage sessions, `rewrite` compacts a session in place, and `fork` seeds a new session from a message slice (used by `--fork`, `/fork` and `/clone`). Appends are fsynced and recover from a partial trailing line. Also stores dynamic-context-pruning compression records so a resumed session rebuilds the same pruned view.
- `src/sessions.rs` — non-interactive session management (`oxide sessions list/delete/compact/merge`) for stale-session cleanup; `delete` filters by id/`--all`/`--older-than`, `compact` summarizes older history into a summary plus recent tail (one LLM pass per session), and `merge` concatenates two sessions or summarizes the second one first.
- `src/snapshots.rs` — shadow-git snapshots (bare repo under `snapshots/<project>/` in the oxide config dir) committed after each agent step; `/undo` and `/redo` in the TUI restore file changes.
- `src/permission.rs` — parses per-agent `permission` rules into allow/ask/deny and decides per tool + subject; `ask` prompts in the TUI unless `auto_approve` is set. The active `Mode` overrides the result: `plan` denies workspace mutations (writes, `bash`, MCP tools), `auto-edit` approves file edits.
- `src/compact.rs` — summarizes long conversation history with the model, keeping the most recent messages; runs automatically when context pruning is disabled, and via `/compact`.
- `src/dcp.rs` — dynamic context pruning: loads `.oxide/dcp.json`, builds the pruned outgoing view (model `compress` summaries, tool-output deduplication, errored-output purging), injects context-limit nudges, and persists compression records through the session log. History is never modified.
- `src/diff.rs` — dependency-free line diff for the TUI: `preview(old, new)` returns `None` when unchanged, a one-line summary when either side exceeds `MAX_DIFF_LINES`, otherwise an LCS-based unified-style preview that keeps `CONTEXT` lines around each change and inserts `⋯` gap markers between disjoint hunks.
- `src/html.rs` — dependency-free HTML to Markdown/plain-text conversion for `webfetch`: a small tag parser, entity decoding, and a renderer for headings, paragraphs, lists, tables, links, images, code, and blockquotes.
- `src/lsp.rs` — minimal LSP client (rust-analyzer, typescript-language-server, pyright, gopls) that reports diagnostics; a `diagnostics` tool is exposed and `write`/`edit` append diagnostics for the edited file.
- `src/plugin.rs` — plugin runtime: loads discovered JS/TS plugins under bun/node with an embedded harness and dispatches `tool.execute.before` / `tool.execute.after` hooks. An `after` hook can rewrite the output and set `output.terminate` to end the turn.
- `src/plugin_registry.rs` — Claude Code-style plugin packages and marketplaces: `oxide plugin` subcommand and TUI `/plugin` manage marketplaces (`.oxide/marketplace.json` preferred, `.claude-plugin/marketplace.json` compatible) and installed plugins (`.oxide/plugin.json` preferred, `.claude-plugin/plugin.json` compatible, bundling commands, agents, skills, MCP servers, and command hooks) under `<config>/oxide/plugins/`. Installed plugins load into the ecosystem before project resources; manifest hooks are translated into a generated JS shim run by the hook host.
- `src/tools.rs` — tool specs and execution under Pi-style names (`read`, `write`, `edit`, `bash`, `grep`, `find`, `ls`, `webfetch`) plus connected MCP tools; legacy aliases (`read_file`, `write_file`, `patch`, `list_dir`, `glob`) are accepted via `canonical_tool_name`, which every name comparison routes through. `execute(call, cwd, &McpRegistry, &Progress)` returns a `ToolOutput` (text plus optional image/PDF media parts, an optional `DiffPreview` for `write`/`edit`, and a `terminate` flag; `read` attaches images/PDFs); `bash` streams stdout/stderr through `Progress`. Output is capped centrally in `execute` by lines (`MAX_OUTPUT_LINES`) and bytes (`MAX_OUTPUT_BYTES`): `bash` keeps its tail so the exit code survives, other tools keep the head, and dropped content is written under `truncated/` in the oxide config dir (`OXIDE_TRUNCATION_DIR`, retained 7 days) with a pointer in the result. `read` trims lines at `MAX_LINE_LEN` and pages via `offset`/`limit`.
- `src/cli.rs` — Pi-compatible non-interactive surface: `@file` argument expansion, the `--tools`/`--exclude-tools` `ToolFilter`, Pi-shaped JSON event framing (`--mode json`) with usage events, and the `--mode rpc` JSONL loop.
- `src/tui/` — ratatui + crossterm interface; renders conversation lines incrementally (only changed items are re-wrapped), keeps shortcuts in the welcome tips, and reserves the status row for current state, spinner and elapsed time. Tool-output bodies are hidden by default (Ctrl+O toggles), shell calls render as concise `Run`/`Ran` actions with a `⋯ Ctrl+O to expand` hint, file edits show a colored line-numbered diff, model turns show `+ Thought: Nms`, and long actions truncate to terminal width. The footer shows cwd, session name, token totals, context percentage, model, mode and thinking level; the labeled input grows to 12 rows and its border reflects the thinking level. Shift+Enter inserts a newline, Shift+Tab cycles mode, Ctrl+R cycles reasoning, Enter while busy queues steering, and Alt+Enter while busy queues a follow-up. It launches without a provider key; `/login` (alias `/connect`) opens a provider/key dialog (bracketed paste enabled) and applies the credential to the running config, startup prompts for project trust when needed, `/trust` saves a decision, `/theme` switches themes and invalidates styled-line caches, and `/help` lists built-in and discovered commands/agents/skills.

## Conventions

- Rust 2021 edition, 4-space indent, default rustfmt style.
- Errors use `anyhow::Result` with `.context(...)` / `.with_context(...)` for human-readable messages.
- Do not add comments unless they explain non-obvious intent.
- Keep changes small and focused; verify with `cargo test` and `cargo clippy`.
- Built-in file/shell tools and connected MCP tools are registered in `tools::specs(&McpRegistry)` and dispatched in `tools::execute(call, cwd, &McpRegistry, &Progress)`. Tool names are canonicalized with `tools::canonical_tool_name`, which accepts Pi names (`read`, `write`, `edit`, `ls`, `find`) and legacy names (`read_file`, `write_file`, `patch`, `list_dir`, `glob`); permission rules, concurrency checks, and TUI rendering must go through it. `edit` is exact-text replacement (`edits[].oldText` must match uniquely against the original file) and stays separate from the unified-diff `patch` tool. `find`/`grep` honor `.gitignore`. The agent-level `task`, `skill`, `memory`, `diagnostics` and `compress` tools are defined and dispatched in `src/agent.rs`.
