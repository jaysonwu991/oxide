# oxide

An optimized AI coding agent CLI written in Rust.

## Layout

- `src/main.rs` — CLI entry (clap). Non-interactive `-p/--print`, `--mode json`, and `--mode rpc` modes plus TUI dispatch; the `mcp`, `sessions`, `plugin`, and `uninstall` subcommands. Provider login is TUI-only (`/login`, `/logout`), matching Pi.
- `src/mcp_config.rs` — `oxide mcp add/list/get/add-json/remove/auth`: reads and writes MCP servers in the native `.oxide/mcp.json` files (`--scope project|global`), merging sources for listing in the same precedence the runtime loads (Claude Code global, `~/.oxide`, the platform config dir, then the project), with a global file reported once as global when the project root resolves to the home directory; `auth` restricts its lookup to the requested `--scope`. `add` also accepts the Claude Code-style `oauth` fields (`--oauth-client-id`, `--oauth-client-secret`, `--callback-port`, `--oauth-scope`, `--redirect-uri`).
- `src/config.rs` — `Config` struct; loads `config.json` from the oxide config dir (`dirs::config_dir()/oxide`, e.g. `~/.config/oxide` on Linux, `~/Library/Application Support/oxide` on macOS) plus `OXIDE_*` / provider env overrides. Provider presets cover OpenAI/GPT, DeepSeek, Anthropic, Portkey, and Z.AI/GLM (`OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `ANTHROPIC_API_KEY`, `PORTKEY_API_KEY`, `ZAI_API_KEY`); Portkey also supports custom gateways/config IDs and model catalogs, and Z.AI is the second provider with a bundled catalog (`GLM_FALLBACK_MODELS`) for `/models`. Defines the `Mode` enum (`build` / `plan` / `auto-edit`, set via `--mode`, `OXIDE_MODE`, or config) and the `Reasoning` enum (`auto` / `off` / `low` / `medium` / `high`, set via `--reasoning`, `OXIDE_REASONING`, or config), composes the system prompt (plan-mode instructions, tool-use guidance that steers toward the dedicated `read`/`grep`/`find`/`ls` tools over compound shell commands, and the loaded ecosystem — listing skills, commands and subagents for model auto-invocation), resolves `/commands` (including `agent`/`subtask` routing and `/skill:<name>`), and loads context-compaction config from `settings.json` and `.oxide/settings.json`. Switching providers remembers the model last used with each one (`provider_models` in `config.json`) so each login keeps its own model, and `for_provider` builds a copy of the config pointed at another logged-in provider for catalog queries.
- `src/auth.rs` — stores provider API keys/tokens for any number of providers side by side in `auth.json` in the oxide config dir (mode 0600); keys are resolved after env vars and before the config file. Authentication is TUI-only (`/login`, `/logout`), matching Pi: `connect` also writes the active provider to `config.json` so the next launch uses it, `select_stored` adopts a provider that is already saved so switching between logged-in providers never asks for the key again, and `stored_providers` lists them. `canonical_provider` maps aliases onto the preset names (`gpt`/`gpt-4o` → `openai`, `port-key` → `portkey`, `glm`/`z.ai`/`zhipu`/`bigmodel` → `zai`). There is no `oxide auth` subcommand.
- `src/ecosystem/` — discovers and loads configuration from project and global scope: the native Oxide layout (`.oxide/`, `AGENTS.md`, `.oxide/mcp.json`) plus the Claude Code layout (`.claude/`, `CLAUDE.md`, `.mcp.json`) for compatibility. Context files (`AGENTS.md`/`CLAUDE.md`, with `AGENTS.override.md` replacing its directory) are collected by walking every ancestor directory down to `cwd`, and `.oxide/SYSTEM.md`/`APPEND_SYSTEM.md` replace or extend the system prompt. Covers instructions, commands, prompt templates (`prompts/*.md` with Pi-style argument expansion), agents/subagents, skills (`SKILL.md`), MCP servers and plugins. Project-scope resources are gated behind project trust via `ecosystem::load_opts`. This repository keeps its own agents, commands, prompts, skills and plugins in `.oxide/`; user-facing configuration guidance lives in `docs/configuration.md`.
- `src/trust.rs` — project trust: `TrustStore` persists per-directory decisions in `trust.json` (closest ancestor wins), `requires_trust` detects project-local resources, `resolve` applies the CLI override plus `defaultProjectTrust` (read from `settings.json`), and untrusted projects reload without project resources (context files still load).
- `src/theme.rs` — semantic TUI color themes: built-in `dark`/`light`, custom `.oxide/themes/<name>.json` (color names or `#rrggbb`), selected with `--use-theme` or `/theme`. Slots cover focus, speakers, success, tools, errors, supporting text, borders, tool panel backgrounds (`tool_pending_bg`/`tool_success_bg`/`tool_error_bg`), the Portkey spend bar (`usage_bar_bg`/`usage_bar_fg`/`usage_bar_label`), thinking levels, and `thinking_text` for reasoning blocks.
- `src/agent.rs` — agent loop: stream the model, execute requested tools, and feed results back until the model stops calling tools or a batch reports `terminate`. Read-only tool calls in a batch run in parallel (results kept in call order) while mutating tools stay sequential; a `Steering` queue injects user messages typed mid-run before the next model call, and a batch whose results all set `terminate` ends the turn. Hosts the agent-level `task` (subagent), `skill` (on-demand load), `command` (model-invoked commands/prompt templates; `subtask` commands run as subagents), `memory`, and `diagnostics` tools; `run` returns a boxed future so subagents can recurse (capped by `MAX_TASK_DEPTH`), and `run_subagent` runs a `subtask` command in an isolated context. A `Runtime` bundles the MCP registry, plugin host, session log, snapshots, LSP manager, the steering and follow-up queues, and the approval callback. Provider-reported token usage (input/output, cache tokens, and cost) is forwarded as `AgentEvent::Usage`, `ThinkingDelta` forwards streamed reasoning and `Retrying` a transient failure about to be retried, `SubagentActivity` carries a nested subagent's tool call up to the originating view (the `task` tool otherwise emits nothing until it returns), and auto-compaction appends a `compaction` entry to the session branch.
- `src/llm/` — model client. `client.rs` dispatches by provider: OpenAI-compatible chat completions (OpenAI, DeepSeek, Portkey, Z.AI/GLM, custom) and the Anthropic Messages API (`anthropic.rs`, converting internal messages to content blocks and parsing its SSE events). Applies the configured reasoning level: OpenAI-compatible `reasoning_effort` and Anthropic adaptive or extended thinking, with Anthropic thinking blocks replayed on later turns; GLM instead toggles `thinking.type` and maps levels onto its own `low`/`high`/`max` scale, asking forced-thinking models (GLM-5.3 and later, via `glm_forces_thinking`) for the lowest effort because they reject `disabled`. Streaming goes through `StreamHooks` (`text`, `thinking`, `retry`) so the caller can show work in progress: reasoning deltas (`reasoning_content`/`reasoning`/`reasoning_text`, normalized by `Delta::reasoning`) are merged into one Anthropic-shaped `thinking` block and forwarded as `AgentEvent::ThinkingDelta`; `types::push_thinking` grows that block in place by mutating its `Value::String`, since rebuilding the block per fragment would copy the whole trace and make a long reasoning stream quadratic, and `types::set_thinking_signature` records the signature Anthropic attaches to it. `read_sse` splits the byte stream with `drain_lines`, which hands each complete line to the caller and compacts the buffer once per chunk instead of after every line. A retryable failure emits `Retry { attempt, max, delay }` before backing off. `stream_chat` retries transient failures (network errors, truncated streams, 429/5xx) with backoff while no text has been emitted, retries a turn that carries neither text nor tool calls (`assistant_turn_is_empty`), and only turns empty/truncated streams or in-band `error` payloads into errors once the retry budget is exhausted. A turn whose provider stop reason is the output limit (`finish_reason`/`stop_reason` `length`/`max_tokens`, captured on `AssistantTurn`) instead retries with a doubled `max_tokens` up to 32768, since a reasoning model that spent the whole budget thinking would only truncate again at the same cap. The Anthropic path shares the empty-turn check and treats a `message_delta` stop reason as completion, so a dropped stream is retried instead of returned as an empty turn.
- `src/mcp.rs` — MCP runtime: connects configured servers over stdio or HTTP, initializes JSON-RPC sessions, and exposes remote tools (`<server>__<tool>`). Remote servers with an `oauth` block attach a bearer token per request.
- `src/mcp_oauth.rs` — OAuth 2.0 authorization-code + PKCE for remote MCP servers: metadata discovery, loopback callback, token exchange/refresh, and `mcp-oauth/<server>.json` storage (mode 0600). The callback answers with a self-contained branded page (semantic color tokens, light and dark via `prefers-color-scheme`, status icon, headline, message naming the server, a monospace block for the provider's error detail, a best-effort `window.close()` after success, all text HTML-escaped, no external assets) plus `Cache-Control: no-store`.
- `src/media.rs` — multimodal attachments: dependency-free base64, image/PDF MIME detection, `@path` reference extraction, and a best-effort OS clipboard image grab (`pngpaste` / `wl-paste` / `xclip`).
- `src/clipboard.rs` — system clipboard writes for the TUI: always emits an OSC 52 sequence (wrapped in a DCS passthrough under tmux/screen, so copies survive SSH) and additionally tries a native helper (`pbcopy`/`osascript`, `wl-copy`/`xclip`/`xsel`). A copy reports itself with a dim `ChatItem::Status` tip, since `App.status` only renders while the agent is busy.
- `src/memory.rs` — persistent cross-session memory store (project + user scope) under `memory/` in the oxide config dir, with dependency-free tf-idf search.
- `src/session.rs` — Pi-compatible session storage under `sessions/<project>/` in the oxide config dir. Each file is a JSONL tree: a `session` header followed by `message`, `compaction`, `branch_summary`, `session_info`, `model_change`, and `thinking_level_change` entries carrying `id`/`parentId`/`timestamp`. The last entry is the active leaf; appending adds a child of the leaf, `branch_with_summary` moves the leaf and appends a branch summary, and `context`/`messages` walk the leaf path with the latest compaction applied. Sessions are resumed via `-c/--continue`, `-r/--resume` (session picker), `--session <path|id>`, or `/resume`; `list` returns picker summaries (id, name, preview, message count), `delete`/`rename` manage sessions, `rewrite` rewrites a session as a linear chain, and `fork` seeds a new session from a message slice (used by `--fork`, `/fork` and `/clone`). Appends are fsynced and recover from a partial trailing line.
- `src/sessions.rs` — non-interactive session management (`oxide sessions list/delete/compact/merge`) for stale-session cleanup; `delete` filters by id/`--all`/`--older-than`, `compact` summarizes older history into a summary plus recent tail (one LLM pass per session), and `merge` concatenates two sessions or summarizes the second one first.
- `src/snapshots.rs` — shadow-git snapshots (bare repo under `snapshots/<project>/` in the oxide config dir) committed after each agent step; `/undo` and `/redo` in the TUI restore file changes.
- `src/permission.rs` — parses per-agent `permission` rules into allow/ask/deny and decides per tool + subject; `ask` prompts in the TUI unless `auto_approve` is set. The active `Mode` overrides the result: `plan` denies workspace mutations (writes, `bash`, MCP tools), `auto-edit` approves file edits.
- `src/compact.rs` — Pi-style context compaction. Walks back from the newest message until `keepRecentTokens` is reached, summarizes the older span with a structured handoff format (including cumulative read/modified file lists), and never cuts between a tool call and its result. Settings live under `compaction` in `settings.json`/`.oxide/settings.json` (`enabled`, `reserveTokens`, `keepRecentTokens`, per-model `modelOverrides`), with `OXIDE_COMPACTION_*` env overrides. Auto-compaction runs in the agent loop once provider-reported usage crosses `contextWindow - reserveTokens`; it appends a `compaction` entry to the session branch anchored at `firstKeptEntryId`, and the session rebuilds the outgoing view from the leaf path. Branch summarization reuses the same structured format: `/tree <n>` branches the current session in place (appending a `branch_summary` entry) and `/fork <n>` creates a new session seeded with the summarized abandoned path. Manual compaction is `/compact [focus]` (TUI) and `oxide sessions compact`.
- `src/diff.rs` — dependency-free line diff for the TUI: `preview(old, new)` returns `None` when unchanged, a one-line summary when either side exceeds `MAX_DIFF_LINES`, otherwise an LCS-based unified-style preview that keeps `CONTEXT` lines around each change and inserts `⋯` gap markers between disjoint hunks.
- `src/html.rs` — dependency-free HTML to Markdown/plain-text conversion for `webfetch`: a small tag parser, entity decoding, and a renderer for headings, paragraphs, lists, tables, links, images, code, and blockquotes.
- `src/lsp.rs` — minimal LSP client (rust-analyzer, typescript-language-server, pyright, gopls) that reports diagnostics; a `diagnostics` tool is exposed and `write`/`edit` append diagnostics for the edited file. A cached server that exits or whose pipe breaks is evicted from the manager (killing the child) and a fresh one is connected before the call is retried, so a one-off crash does not turn every later edit into `Broken pipe`; EOF while awaiting diagnostics is treated as a disconnect rather than a clean result.
- `src/plugin.rs` — plugin runtime: loads discovered JS/TS plugins under bun/node with an embedded harness and dispatches `tool.execute.before` / `tool.execute.after` hooks. An `after` hook can rewrite the output and set `output.terminate` to end the turn; a `status` hook returns keyed strings for the footer's third row.
- `src/pricing.rs` — model prices for the footer's `$cost` segment. Ships a small default table (USD per million tokens, including the GLM models) overlaid by a `modelPrices` map in `settings.json`/`.oxide/settings.json`; unknown models cost 0 and the segment is omitted.
- `src/portkey_usage.rs` — the Portkey spend status bar. `/usage on|off|user|budget|currency|key|metadata` in the TUI configures it (it only runs while a Portkey provider is logged in, since it reads that account's spend); settings and the API key live in `portkey-usage.json` in the oxide config dir (mode 0600, `OXIDE_USAGE_FILE` override). `spend` queries `GET <base_url>/analytics/graphs/cost` with `x-portkey-api-key` filtered by the configured user metadata (`_user` by default) for the local day and month, and the bar adds the session's own `$cost`; the key falls back to the active Portkey credential, the budget is formatted in the configured currency (`usd`/`cny`), and the bar refetches every 60s and after each turn.
- `src/plugin_registry.rs` — Claude Code-style plugin packages and marketplaces: `oxide plugin` subcommand and TUI `/plugin` manage marketplaces (`.oxide/marketplace.json` preferred, `.claude-plugin/marketplace.json` compatible) and installed plugins (`.oxide/plugin.json` preferred, `.claude-plugin/plugin.json` compatible, bundling commands, agents, skills, MCP servers, and command hooks) under `<config>/oxide/plugins/`. Installed plugins load into the ecosystem before project resources; manifest hooks are translated into a generated JS shim run by the hook host.
- `src/tools.rs` — tool specs and execution under Pi-style names (`read`, `write`, `edit`, `bash`, `grep`, `find`, `ls`, `webfetch`) plus connected MCP tools; legacy aliases (`read_file`, `write_file`, `patch`, `list_dir`, `glob`) are accepted via `canonical_tool_name`, which every name comparison routes through. `execute(call, cwd, &McpRegistry, &Progress)` returns a `ToolOutput` (text plus optional image/PDF media parts, an optional `DiffPreview` for `write`/`edit`, and a `terminate` flag; `read` attaches images/PDFs); `bash` streams stdout/stderr through `Progress`. Output is capped centrally in `execute` by lines (`MAX_OUTPUT_LINES`) and bytes (`MAX_OUTPUT_BYTES`): `bash` keeps its tail so the exit code survives, other tools keep the head, and dropped content is written under `truncated/` in the oxide config dir (`OXIDE_TRUNCATION_DIR`, retained 7 days) with a pointer in the result. `read` trims lines at `MAX_LINE_LEN` and pages via `offset`/`limit`. `read`/`ls`/`find`/`grep` accept absolute paths; `ls` renders symlink targets as `name -> target`; `grep` matches a literal substring and prefers `ripgrep` when it is on `PATH`, falling back to a parallel built-in walker that sniffs and skips binary files.
- `src/cli.rs` — Pi-compatible non-interactive surface: `@file` argument expansion, the `--tools`/`--exclude-tools` `ToolFilter`, Pi-shaped JSON event framing (`--mode json`) with usage events, and the `--mode rpc` JSONL loop.
- `src/uninstall.rs` — removes oxide's binary and data for `oxide uninstall`: detects Cargo/Homebrew/prebuilt installs, honors `--keep-config`/`--keep-data`, and previews with `--dry-run`.
- `src/tui/` — ratatui + crossterm interface; renders conversation lines incrementally (only changed items are re-wrapped), shows the block-letter `OXIDE` wordmark above a short banner summary, and reserves the status row for current state, spinner and elapsed time. Tool calls render as background-filled panels colored by state (`tool_pending_bg`/`tool_success_bg`/`tool_error_bg`) with the action header, a blank line, the body, a blank line before the `Took` footer, all inside one block; bodies are shown by default (Ctrl+O collapses to a `⋯ Ctrl+O to expand` hint), shell calls read as concise `Run`/`Ran` actions (with a `(timeout Ns)` hint, a live `Elapsed Ns` while running, and a `Took Nms` duration; every other tool panel ticks a live `Elapsed` too and shows `Took` once it exceeds 500ms), `task` panels additionally carry a `↳ <agent> · <activity> · <n> call(s)` line fed by `AgentEvent::SubagentActivity` (so a long subagent is not silent), `read` results show the file content, file edits show a colored line-numbered diff, user and assistant turns render their label inline with the message text, reasoning renders as a muted italic `✦ Thinking` block that closes with `✦ Thought for <duration>` (see `ChatItem::Thinking`), and long actions and wrapped tool output use a hanging indent so their full text stays readable. The footer matches Pi: row one is the `~`-abbreviated cwd with the git branch in parentheses and ` • ` session name; row two is dim cumulative usage (`↑`/`↓` plus `R`/`W` cache tokens and `CH` hit rate when the provider reports cache, and `$cost` from the model price table), context `%`/window with an `(auto)` marker (colored above 70/90%), and the right-aligned `(provider) ` model and, when the model supports reasoning, ` • ` thinking level; a third dim row appears when plugins contribute statuses via the `status` hook; when the Portkey spend bar is enabled and a Portkey provider is logged in, a final full-width `usage_bar_*`-colored row shows `→ <user> | Session/Today/Month` spend. Totals are restored from the session on resume. The composer matches Pi's editor: full-width top and bottom rules (no side borders, corners, or prompt) colored by the thinking level, growing to 12 rows, with the working status embedded in the top rule while busy (a phase set by `handle_agent_event`, including `retrying (n/m) in Ns...` for a stream retry). Shift+Enter inserts a newline, Shift+Tab cycles mode, Ctrl+R cycles reasoning, Ctrl+O collapses tool bodies, Ctrl+T collapses `✦ Thinking` blocks (start hidden with `hideThinkingBlock` in `settings.json`), Enter while busy queues steering, Alt+Enter while busy queues a follow-up, and `Alt+Up` (`Alt+Q` on Windows/WSL, `Option+Up` on macOS) pulls every queued message back into the composer to be extended before sending. Feedback for actions taken while idle — a copy, Ctrl+O, Ctrl+T, a mode or theme switch — is a dim `ChatItem::Status` line in the transcript that replaces the previous tip, because the busy-phase `App.status` only renders inside the composer rule. It launches without a provider key; `/login` (alias `/connect`) opens a provider/key dialog (bracketed paste enabled) that marks providers with a stored credential and reuses their key on Enter (a second `/login <provider>` switches to one directly), applies the credential to the running config, and `/logout` falls back to another logged-in provider instead of clearing the session; `/models` lists the catalogs of every logged-in provider at once, tagged per provider, and selecting a model from another one switches to it. Startup prompts for project trust when needed, `/trust` saves a decision, `/theme` switches themes and invalidates styled-line caches, `/usage` configures the Portkey spend bar, and `/help` lists built-in and discovered commands/agents/skills.

## Conventions

- Rust 2021 edition, 4-space indent, default rustfmt style.
- Errors use `anyhow::Result` with `.context(...)` / `.with_context(...)` for human-readable messages.
- Do not add comments unless they explain non-obvious intent.
- Keep changes small and focused; verify with `cargo test` and `cargo clippy`.
- Built-in file/shell tools and connected MCP tools are registered in `tools::specs(&McpRegistry)` and dispatched in `tools::execute(call, cwd, &McpRegistry, &Progress)`. Tool names are canonicalized with `tools::canonical_tool_name`, which accepts Pi names (`read`, `write`, `edit`, `ls`, `find`) and legacy names (`read_file`, `write_file`, `patch`, `list_dir`, `glob`); permission rules, concurrency checks, and TUI rendering must go through it. `edit` is exact-text replacement (`edits[].oldText` must match uniquely against the original file) and stays separate from the unified-diff `patch` tool. `find`/`grep` honor `.gitignore`; `grep` prefers `ripgrep` when available and otherwise uses a parallel built-in walker. The agent-level `task`, `skill`, `command`, `memory`, and `diagnostics` tools are defined and dispatched in `src/agent.rs`.
